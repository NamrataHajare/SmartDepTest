# SmartDepTest VS Code Extension

This extension wraps the existing Java-based SmartDepTest analysis engine. It adds a dedicated Activity Bar view for starting analysis, viewing status, and reviewing the current session history.

## Setup

1. Ensure Java 21 or newer is installed and available on `PATH`.
2. Ensure the original SmartDepTest project exists in a sibling directory or at the configured location.
3. Install dependencies and compile the extension:

```powershell
cd "C:\Users\HP\OneDrive\Desktop\Documents\Mega Project\SmartDepTest-VSCode"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
npm install
npm run compile
```

## Configuration

Use the VS Code settings under `SmartDepTest`:

- `smartDepTest.componentPath`: path to the Java SmartDepTest project root.
- `smartDepTest.projectPath`: optional target Maven Git project to analyze.
- `smartDepTest.javaPath`: Java executable path if needed.
- `smartDepTest.timeoutMs`: execution timeout in milliseconds.

The default component path points to the sibling `../SmartDepTest` folder relative to this extension project.

## Usage

1. Click the SmartDepTest icon in the Activity Bar.
2. Use the visible Start Analysis button.
3. Pick the target Maven Git project if prompted.
4. On successful analysis, the extension creates a standalone HTML impact report in the selected project's `target` directory and opens it with the operating system's default application. A run-specific report path is kept in session history.
5. In the sidebar, select a previous run to review the text report and structured results. Use **Open HTML Impact Report** to reopen its HTML file, **Save Report** to save a `.txt` copy, or the separate buttons to export that run's JSON artifacts.

## Notes

- This extension tracks all runs in memory for the current VS Code session.
- HTML reports are generated as `target/smartdeptest-impact-report-<run>-<timestamp>.html` and are self-contained. Text reports and JSON exports are still saved only when you choose an export destination; JSON files are snapshotted per run in memory so later runs cannot replace an older run's exports.
- It does not persist run history across restarts.
- Source links in the HTML use the VS Code `vscode://file/<path>:<line>` URI handler. The report also displays each available source path and line as a fallback because browsers or operating-system settings can block custom-protocol links. Sidebar navigation continues to open source in VS Code directly.
- The report uses only the engine's current-run impact-graph and coverage-selection JSON. Missing or invalid artifacts prevent a report from being marked successful; limitations and unresolved source/test mappings are called out explicitly. Static test candidates are not claims of runtime coverage or test failure, and selecting no tests is not proof of no dependency impact.
- The existing Maven analysis and JSON/text output formats remain in use; the report is generated by the extension without changing the dependency-impact or test-selection algorithms.

## Packaging

```powershell
npm run package
```

This creates a `.vsix` from the extension project.
